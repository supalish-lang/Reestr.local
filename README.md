# Реестр входящих заявок

Веб-страница для учёта писем-заявок на рассмотрение проектов. Страница лежит на GitHub Pages, данные и права доступа хранятся в Supabase.

- **Руководитель** (роль `manager`): видит все заявки, только просмотр, выгрузка в CSV.
- **Исполнитель** (роль `executor`): видит и меняет только свои заявки.
- Рекомендуемый срок (+5 рабочих дней) и крайний срок (+15 рабочих дней) считает база данных, вручную их изменить нельзя.

Сотрудникам не нужны аккаунты GitHub, Supabase или Claude: достаточно ссылки, логина и пароля.

## Файлы

| Файл | Назначение |
|---|---|
| `index.html` | вся страница |
| `schema.sql` | таблицы, расчёт сроков и права доступа для Supabase |
| `README.md` | эта инструкция |

## 1. Создать проект в Supabase

1. Зарегистрируйтесь на supabase.com и создайте проект (New project), запишите пароль базы.
2. Откройте **SQL Editor → New query**, вставьте весь `schema.sql` и нажмите **Run**.
3. Откройте **Authentication → Sign In / Providers** (в старых интерфейсах **Providers → Email**):
   - выключите **Allow new users to sign up** (регистрироваться могут только созданные вами пользователи);
   - выключите **Confirm email**.
4. Откройте **Project Settings → API** и скопируйте:
   - **Project URL**;
   - **anon public** key. Ключ `service_role` в репозиторий не копировать никогда.

## 2. Создать пользователей

Для каждого сотрудника:

1. **Authentication → Users → Add user → Create new user**.
   - Email: `логин@reestr.local`, например `ivanov@reestr.local`.
   - Password: пароль сотрудника.
   - Включите **Auto Confirm User**.
2. В **SQL Editor** выдайте профиль и роль.

Исполнитель:

```sql
insert into public.profiles (id, login, full_name, role)
select id, 'ivanov', 'Иванов Иван', 'executor'
from auth.users where email = 'ivanov@reestr.local';
```

Руководитель (трое):

```sql
insert into public.profiles (id, login, full_name, role)
select id, 'petrov', 'Петров Пётр', 'manager'
from auth.users where email = 'petrov@reestr.local';
```

Сотрудник входит на сайте под логином `ivanov` (без `@reestr.local`).

Сменить пароль: Authentication → Users → пользователь → Send password recovery / Reset password. Отключить сотрудника: удалить его в Users.

Если Supabase отклоняет адрес с доменом `.local`, замените его на другой служебный домен в двух местах: в имени пользователя и в константе `LOGIN_DOMAIN` в `index.html`.

## 3. Подключить страницу к Supabase

В начале скрипта в `index.html` впишите:

```js
const SUPABASE_URL = "https://xxxx.supabase.co";
const SUPABASE_ANON_KEY = "ваш anon public key";
```

Anon-ключ публичный по замыслу: данные защищает не он, а права доступа (RLS) из `schema.sql`.

## 4. Выложить на GitHub Pages

1. Создайте репозиторий и загрузите `index.html`, `schema.sql`, `README.md`.
2. **Settings → Pages → Build and deployment → Deploy from a branch → `main` / `(root)` → Save**.
3. Через минуту-две страница откроется по адресу `https://<аккаунт>.github.io/<репозиторий>/`. Эту ссылку отправьте сотрудникам.

В публичном репозитории код страницы виден всем, но заявки видны только вошедшим пользователям в рамках их роли.

## 5. Праздники

Рабочие дни считаются без суббот, воскресений и дат из таблицы `holidays`. В `schema.sql` заложены только ближайшие праздники. Раз в год добавляйте официальные праздники и переносы выходных (по постановлению Правительства РК):

```sql
insert into public.holidays (day, note) values ('2027-03-22', 'Наурыз') on conflict do nothing;
```

Даты, выпавшие на субботу или воскресенье, добавлять не нужно, а день переноса нужно. Рабочие субботы (переносы с будних дней) расчёт не учитывает.

Сроки уже созданных заявок не пересчитываются при добавлении праздников. Чтобы пересчитать, выполните:

```sql
update public.requests set received_date = received_date;
```

## 6. Проверка после запуска

1. Войдите исполнителем, создайте заявку: сроки появились, заявка видна.
2. Войдите другим исполнителем: чужой заявки нет.
3. Войдите руководителем: видны все заявки, значков редактирования нет.
4. Создайте заявку со сроком через праздник и проверьте даты.

## Ограничения

- Бесплатный проект Supabase ставится на паузу после недели без активности: тогда войдите в панель Supabase и нажмите Restore.
- Один исполнитель на заявку, передача другому не предусмотрена.
- История смены статусов и вложения не поддерживаются.
